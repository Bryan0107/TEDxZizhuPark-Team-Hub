# TEDxZizhuPark Team Hub 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 产品名称 | TEDxZizhuPark Team Hub |
| 产品形态 | Web 网页端管理系统（响应式，兼容桌面与移动端浏览器） |
| 产品定位 | TEDx 紫竹年度团队运营、成员贡献记录及内部积分管理平台 |
| 文档版本 | V1.0（第一稿） |
| 目标用户 | TEDx 核心组织者、各组组长、团队成员 |
| 设计原则 | 轻量化、可量化、可追溯、透明化、鼓励参与 |

---

## 1. 项目背景与产品目标

### 1.1 背景

TEDx 紫竹由多个职能团队协作完成活动策划、品牌传播、视觉设计、嘉宾邀请、场地协调、合作伙伴管理与社区运营。当前协作存在以下问题：

1. 成员参与情况分散在微信群、飞书文档和日常沟通中，缺乏统一记录。
2. 各组工作量与实际贡献难以横向比较，投入情况不透明。
3. 组长向核心管理团队汇报缺少统一的数据填报与统计工具。
4. 成员长期贡献难以沉淀，年度总结容易遗漏个人付出。
5. 缺少统一的内部积分机制，无法通过数据与激励增强参与感。

### 1.2 产品目标

建立三个相互关联的管理体系：

- **A. 成员贡献管理**：统一成员档案；记录活动、任务与贡献；通过积分量化；支持年度排名与历史查询。
- **B. 团队工作管理**：组长每月提交团队工作报告；记录组员参与与团队整体工作量；支持核心管理团队审核、查看与汇总。
- **C. 年度组织数据管理**：形成年度工作数据库；查看各组工作量、活跃度与积分分布；支持年度总结表彰与下一年度人员安排参考。

## 2. 用户角色与权限（RBAC）

### 2.1 超级管理员 Admin

主要用户：TEDx 核心组织者、年度总负责人。

权限：创建/编辑/停用团队；创建/邀请/编辑/管理成员；分配组长；设置积分规则与权重；查看与审核全部月报（通过/驳回）；手动调整积分；全组织统计看板；导出全部数据；管理年度与历史数据。

### 2.2 团队组长 Team Leader

主要用户：各职能团队负责人。

权限：查看本组成员名单及历史参与；每月填写提交团队月报；登记成员参与情况；登记团队工作量与成果；提出积分建议；查看本组工作量统计与成员积分；修改未提交月报；查看审核意见并重提被驳回月报。

限制：不得修改其他团队数据；不得直接修改已审核积分；不得删除已审核历史记录。

### 2.3 普通成员 Member

权限：查看个人资料、积分及明细、月度参与记录、年度贡献；查看团队公告、积分规则与组织公开成果；对个人参与记录提出异议或补充说明。

限制：不得修改组长提交的已审核记录；不得查看其他成员的私人评价或管理备注。

### 2.4 管理人员 Reviewer（可选）

由核心管理团队项目运营人员担任。可查看全部月报、审核月报、提出修改意见、查看统计报表；不具备系统配置与积分规则修改权限。

## 3. 核心功能模块

### 3.1 模块一：年度管理驾驶舱 Dashboard

登录后首页，按角色展示不同内容。

**核心数据卡片**：年度累计积分、团队数量、有效成员数、本月已提交/待审核月报数、本月团队累计工作量、本月活跃成员数、本年度累计成果数。

**团队工作概览**：卡片或表格展示各团队名称、组长、成员数、本月任务数、完成数、工作量、参与人数、月报提交状态。

**年度趋势分析**：月度组织总工作量趋势、月度活跃成员趋势、各团队工作量对比、各团队积分贡献分布、年度成员积分排行榜；支持年度/季度/月份筛选。

**角色化首页**：
- 组长首页：本月月报填报入口、本组成员参与、本月任务、审核状态、团队工作量。
- 普通成员首页：个人年度积分、本月新增积分、贡献记录、参与历史、年度进度。
- 管理员首页：组织运行概况、各组月报进度、待审核、活跃度、年度排行、团队对比。

### 3.2 模块二：内部积分管理 Points System

**设计原则**：积分记录实际贡献而非简单出勤。采用「基础参与 + 任务贡献 + 特别贡献 + 组织贡献 + 社区贡献」结构。所有积分必须有明确来源、记录时间与审核记录。

**积分类型与建议规则（V1.0 默认值，管理员可调）**：

| 行为 | 积分 |
|---|---:|
| 参加正式团队例会 | +2 |
| 参加专项培训 | +2 |
| 完成普通任务 | +3 |
| 完成重要任务 | +5 |
| 完成重大项目交付 | +10 |
| 跨组协作并完成交付 | +3 |
| 参与活动现场执行 | +5 |
| 主动承担额外工作 | +3 |
| 协助招募并完成成员引入 | +3 |
| 组织一次有效社区活动 | +5 |
| 获得特别贡献认定 | +5～20（管理员审核） |

注意：同一事项不重复计分；任务积分以实际交付为依据；不按工作时长计分；组长只能提出积分建议，不能修改最终积分。

**操作流程**：组长月报登记事项 → 系统按规则生成建议积分 → 组长确认/调整建议 → 管理员审核月报及积分 → 通过后积分自动入账 → 成员可查明细。

**积分账户**：展示当前年度累计、历史累计、本月新增、各类构成、积分流水、来源与审核状态。流水不可删除；错误通过反向调整修正并保留原因。

**排行榜**：年度个人榜、月度个人榜、团队榜、特别贡献榜；管理员可开关；默认只展示年度与团队积分，不作为唯一价值评价。

### 3.3 模块三：月度团队工作报告 Monthly Report

组长每月必交一次。状态：未开始 → 填写中 → 待提交 → 审核中 → 待修改 → 已通过。

**第一部分 团队整体工作（组长填写）**：所属月份（自动生成）、团队（自动关联）、本月工作总结、本月核心目标、本月完成事项、本月未完成事项、当前主要问题、下月工作计划、需要其他团队支持事项（后三项选填）。

**第二部分 团队工作量统计**：采用任务记录制，每条任务包含名称、所属项目、类型（活动策划/内容创作/视觉设计/品牌传播/嘉宾管理/合作伙伴/社区运营/行政后勤/现场执行/其他）、负责人、参与成员（多人）、起止日期、状态（未开始/进行中/已完成/暂停/取消）、重要程度、预计时长、实际工时（可选）、交付成果、成果链接、备注。系统自动汇总任务总数、完成数、进行中数、总工时、涉及成员数、跨组协作次数。

**第三部分 组员月度参与登记**：每成员一行可展开编辑，字段包括姓名（自动）、参与状态（活跃/正常/低频/暂未参与）、参与任务数（自动统计）、活动次数、主要参与事项、个人贡献说明、建议积分（自动计算）、组长评价（优秀/良好/一般/待改善）、额外贡献、是否需要跟进。支持批量录入与单人编辑。暂未参与不自动扣分。

**第四部分 团队总结及协作评价**：本月最重要成果、最值得肯定的成员及原因、跨组合作情况、组织问题、对核心团队建议。

**提交与审核**：通过→进入历史档案、积分自动入账、统计自动更新；退回→组长收到意见、可修改重提。已通过月报锁定，调整由管理员发起修订并保留历史版本。

### 3.4 模块四：成员管理 Member Directory

字段：姓名、头像、邮箱、所属团队、职务、加入时间、状态（正常/暂停参与/已退出/历届成员）、简介、历史参与年度、当前年度积分、历史累计积分。支持一人多团队（需设主归属）；历届档案保留，服务十周年社区与历届成员 reconnect。

### 3.5 模块五：团队管理 Team Management

管理员创建团队：名称、介绍、组长、副组长（可选）、成员、成立时间、状态。支持添加/移除成员、更换组长、调整归属、查看历史月报与年度贡献。

### 3.6 模块六：数据分析与年度总结 Analytics

- **组织整体**：年度总积分、总任务数、完成数、月度平均活跃人数、参与率、各团队完成率、协作次数。
- **团队分析**：月度工作量趋势、完成率、成员参与、积分分布、月度成果对比。
- **个人贡献报告**：全年累计积分、参与月份、任务数、活动次数、主要贡献项目、特别贡献记录、所属团队、组长年度评价；支持导出。
- **数据导出**：Excel/CSV 导出成员名单、积分流水、月度报告、任务清单、参与记录、年度统计。

### 3.7 页面结构与导航

左侧固定导航：首页 Dashboard、我的积分 My Points、团队管理 Teams、月度报告 Monthly Reports、任务管理 Tasks、成员管理 Members、积分管理 Points Management、数据分析 Analytics、系统设置 Settings。按角色自动隐藏无权限菜单。

### 3.8 多语言

界面支持简体中文 / English 切换，语言选择持久化保存。V1.0 覆盖导航、页面标题、驾驶舱及主要操作文案。

## 4. 交互与视觉设计

- **风格**：Professional、Minimal、Editorial、Community-driven、Data-oriented。
- **视觉**：白/浅灰主背景，TEDx 红（#E62B1E）强调色，深灰文字，清晰数据卡片，简洁图表，适度留白。
- **品牌**：官方 TEDxZizhuPark 黑白 Logo（`public/assets/logo-black.png` / `logo-white.png`）。
- **填报体验**：月报自动生成当月记录并读取本组成员；任务数据自动汇总；草稿保存；批量登记；复制上月基础信息；自动保存进度；提交前完整性检查；适配桌面与移动浏览器。

## 5. 通知机制

V1.0 站内通知：填报开始、截止提醒、已提交、审核通过、被退回、积分到账、积分调整。后续可接入飞书机器人。

## 6. 非功能需求

权限隔离；密码加密存储；积分与审核记录完整保存；关键操作留审计日志；常规页面加载 < 3s；兼容 Chrome/Safari/Edge；响应式布局；定期备份；支持多组长并发提交。

## 7. 数据结构建议（关系型）

users、members、teams、team_members、monthly_reports、monthly_member_records、tasks、task_members、points_rules、points_transactions、report_reviews、audit_logs。要求：成员唯一 ID；流水关联成员与来源；月报记录年度月份；任务多人参与；已审核月报留版本；积分变更可追溯；成员退出保留历史；不允许删除成员抹除历史积分。

## 8. MVP 范围

**P0 必须**：登录与角色权限、团队与成员管理、月报填写、参与登记、任务记录、提交与审核、积分规则、积分自动计算与流水、管理员看板、Excel 导出。

**P1**：个人年度贡献报告、团队年度对比、排行榜、飞书通知、个人主页、历届档案。

**P2**：社区活动管理、志愿者招募、跨年度档案、积分兑换激励、合作伙伴管理。

## 9. 验收标准

1. 管理员可创建团队并添加成员、指定组长。
2. 组长只能管理自己的团队。
3. 组长可创建当月月报并批量登记成员参与。
4. 可添加任务并关联多位成员，自动统计任务数、完成数、工作量。
5. 系统按规则计算建议积分；管理员可审核月报；通过后积分正确入账。
6. 成员可查看自己的积分明细。
7. 管理员可查看全部团队数据并导出月报与年度积分。
8. 历史积分不可直接删除。

## 10. 待确认决策

1. 积分周期：建议年度积分与历史总积分并存（不清零）。
2. 审核策略：建议月报统一审核，普通积分自动计算，特别贡献额外审核。
3. 多团队归属：建议允许，设主归属。
4. 工时记录：建议支持填写但不作为唯一绩效指标。
5. 排行榜开放范围：建议默认可见年度积分，管理员可控。
6. 历届成员：建议保留档案，仅实际参与者计入本年度活跃。

## 11. 产品愿景

TEDxZizhuPark Team Hub 不只是内部管理后台，更是 TEDx 紫竹的**年度组织记忆系统**——让每一位成员看见自己的付出，让每一位组长清晰呈现团队成果，让核心管理团队从数据中理解组织运行。我们做的不是简单的绩效考核，而是让每一次参与、每一份贡献、每一个共同完成的项目都被记录、被看见、被认可。
